## 晚高峰为什么会卡：四个叠加的成因

**物理距离决定下限。** 中国大陆到美国西海岸直线约 10000 公里，数据往返一趟的理论极限在 130ms 左右。这条线以下不可能，所以“美国 VPS 延迟 50ms”是纯粹的假宣传。

**时差制造双高峰。** 北京时间 20:00–23:00 对应美西当天 08:00–11:00，北美企业业务刚开工、个人用户也起来了，跨太平洋海缆同时承载两边流量。行业监测显示，UTC+8 时区的 20:00–23:00，美亚之间延迟往往增加 20%–30%。这是物理层面的拥堵，任何优化手段都只能绕开，不能消除。

**机房位置和线路等级拉开差距。** 洛杉矶、圣何塞对亚洲最近，物理延迟 130–170ms；中部或东海岸节点，或者走 HE、Cogent 这类普通线路，晚高峰实测飙到 350ms 以上、丢包超过 5% 都很常见。

**超售和隐性限速。** 一台物理机开出远超正常数量的虚拟机，晚间 CPU 争用、内存紧张、磁盘 I/O 拥堵同时爆发。标榜“不限流量”的套餐还常见一条条款：流量超过某个阈值后自动 QoS 限速，带宽从高速路变成乡间小道。这种慢和线路拥堵是两回事，判断方法也不同：前者任何时段都慢，后者只在晚高峰慢。

## 回程比去程更决定体验

网页、API、视频都是“小请求、大响应”：你发出去几十字节的 GET 请求，服务器返回几 MB 的页面数据。回程走普通 163 骨干网，晚高峰丢包一飙升，用户端看到的就是“网页加载一半卡住”“接口超时”“SSH 敲两行等半分钟”。

所以商家只提“去程优化”的时候要警惕。CN2 GT 就是典型：去程可能走优质节点，回程大概率切回拥堵的 163 骨干网。

## 三条精品线路，“三网优化”到底优化了哪三段

- **CN2 GIA（AS4809）**：中国电信最高等级国际精品网，去回程全程走 59.43 专属节点，独立于公共互联网，有最高 QoS 优先级。成本最高，搭载它的机器通常不便宜。
- **AS9929 / CUII**：中国联通国际精品骨干网，联通方向上的对标方案，国内到洛杉矶延迟通常稳定在 150–180ms。
- **CMIN2**：中国移动二代国际承载网，移动宽带用户走这条回程比普通国际出口稳得多。

所谓“三网优化”，就是把这三段各走各家精品：电信走 CN2 GIA、联通走 AS4837 或 9929、移动走 CMI 或 CMIN2。做不到这一点的方案，通常只优化电信，联通和移动用户自求多福。

一条 5M 的 CN2 GIA 线路，实际体验往往胜过 100M 的普通 BGP 共享线路。带宽数字大不等于快，线路等级才是决定晚高峰表现的那一项。

## 丢包率比 Ping 值更能决定体验

平均延迟 160ms 看着不错，但如果同时有 5% 的丢包，实际体验会很差。TCP 协议下丢包触发重传，5% 意味着每 20 个数据包就有 1 个要重发，有效吞吐量呈断崖式下跌。表现就是页面加载奇慢、文件下载到一半卡死、SSH 长连接莫名断开。

这也解释了一个常见困惑：为什么有些机器 ping 出来延迟不高，用起来却很卡。看平均延迟只是第一步，丢包率和最大延迟才是决定体感的那两项。

## 买之前自己测：三条命令和一份判读表

商家的宣传图不可信，自己动手十分钟就有结论。测试必须在晚上 20:00–23:00 做，白天测什么线路都是好的。

1. **连续 Ping 100 次**：Windows 用 `ping -n 100 目标IP`，Linux/macOS 用 `ping -c 100 目标IP`。记录平均延迟、最大延迟、丢包率三项。最大延迟和平均值差距大，说明链路有间歇性拥塞。
2. **回程路由追踪**：`mtr -rwzc 100 目标IP`。重点看回程方向，也就是靠后的那些跳。
3. **判读节点号段**：全程大量出现 59.43 开头，是真正的 CN2 GIA；出现 202.97 节点，说明回程回落到了 163 骨干网；路径里莫名其妙出现日本或欧洲节点，说明发生了严重绕路。
4. **特殊处理**：目标机器如果屏蔽 ICMP，ping 会全部超时，这不等于机器挂了。改用 tcping 打它的 SSH 端口或你实际使用的业务端口，或者用 `mtr -T` 走 TCP 模式。

SixtyNet 就属于需要特殊处理的那一类。有第三方测评提到，官方屏蔽了 ICMP 回显，也屏蔽了 80 和 443 端口，所以拿到 IP 之后 ping 不通是正常现象，别急着开工单。
